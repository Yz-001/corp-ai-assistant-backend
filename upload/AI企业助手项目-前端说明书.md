# AI企业助手项目（前端）开发说明书

**文档类型：AI编码执行版**
**适用对象：AI代码生成 / 前端开发 / Vue3 项目实现**
**技术栈：Vue 3 + TypeScript + Element Plus + Pinia + Vue Router + Vite**
**当前版本：v2.0**

---

# 1. 项目目标

构建一个面向企业使用的 AI 助手前端系统，支持以下两类核心场景：

## 1.1 普通用户场景

普通用户进入系统后，主要使用 AI 对话能力，包括：

* 新建会话
* 查看历史问话
* 多轮对话
* 查看推荐提示词和可提问问题
* 查看回答引用来源
* 在 PC 和移动端 H5 上正常使用

## 1.2 管理员场景

管理员除聊天能力外，还需要看到完整后台能力，包括：

* 租户管理
* 文档上传与文档管理
* 日志管理
* 工具管理
* MCP 工具接入管理
* 系统监控看板
* 当前在线人数、调用流量、Tokens 消耗等统计信息

---

# 2. 项目定位

这是一个**前后端分离的企业级 Web 应用前端**，需同时满足：

* **桌面端后台管理体验**
* **聊天主界面产品体验**
* **移动端 H5 可访问与可用**
* **后续支持多租户、权限控制、工具扩展**

前端要优先保证：

1. 页面结构清晰
2. 组件拆分合理
3. 状态管理规范
4. 权限路由清晰
5. 响应式布局完整
6. 易于 AI 持续增量生成和维护

# 3. 技术栈要求

## 3.1 必须使用

* Vue 3
* TypeScript
* Vite
* Vue Router
* Pinia
* Element Plus
* Axios
* SCSS

## 3.2 推荐使用

* `@vueuse/core`
* `unplugin-auto-import`
* `unplugin-vue-components`
* `@element-plus/icons-vue`
* `dayjs`
* `lodash-es`
* `echarts`
* `nprogress`

## 3.3 开发约束

* 必须使用 Composition API
* 组件必须尽量使用 `<script setup lang="ts">`
* 状态统一通过 Pinia 管理
* 网络请求统一封装
* 权限控制必须基于路由 + 菜单 + 页面按钮三层实现
* 页面样式必须兼容桌面端和移动端
* 不允许把大段业务逻辑堆在单个页面中

# 4. 适配要求

## 4.1 适配范围

前端必须适配以下屏幕范围：

* **大屏桌面端**：1920px 及以上
* **常规桌面端**：1440px / 1366px / 1280px
* **平板端**：1024px / 768px
* **手机 H5**：430px / 390px / 375px / 360px

## 4.2 响应式策略

采用 **桌面优先 + 响应式降级** 方案：

### 大屏 / PC

* 左右布局完整展示
* 左侧侧边栏固定
* 右侧聊天区 / 管理区展开显示
* 顶部信息栏完整展示

### 平板

* 左侧栏可折叠
* 部分表格列自动收起
* 表单弹窗宽度缩小
* 仪表盘图表单列或双列排布

### 手机 H5

* 左侧历史会话改为抽屉式侧滑
* 顶部显示页面标题和菜单按钮
* 表格改为卡片列表优先
* 筛选条件支持折叠
* 聊天输入区固定底部
* 提示词改为横向滚动或分行标签
* 图表按单列显示
* 管理页面保留核心功能，不追求桌面端复杂布局

## 4.3 布局断点建议

```ts
xs: < 768
sm: >= 768
md: >= 992
lg: >= 1200
xl: >= 1440
xxl: >= 1920
```

# 5. 用户角色与权限

## 5.1 角色定义

前端至少支持以下角色：

* `super_admin`：平台超级管理员
* `tenant_admin`：租户管理员
* `tenant_user`：普通租户用户
* `public_user`：外部访客 / 轻用户

## 5.2 权限差异

### public_user

只能访问：

* 官网聊天页 / 公共问答页

### tenant_user

可以访问：

* 聊天页
* 历史会话
* 推荐问题
* 文档引用来源查看
* 自己权限范围内的知识问答

### tenant_admin

可以访问：

* 聊天页
* 文档上传与管理
* 日志查看
* 工具管理（租户内）
* 基础统计看板

### super_admin

可以访问全部：

* 租户管理
* 用户与角色管理
* 文档管理
* 日志与审计
* 工具 / MCP 管理
* 系统监控
* 在线人数 / 流量 / Tokens 统计

# 9. 聊天页设计

这是最核心页面，必须重点实现。

## 9.1 布局要求

聊天页采用**左侧历史会话 + 右侧当前会话区域**布局。

### PC 布局

```text
┌────────────────────────────────────────────────────────────┐
│ Header                                                     │
├────────────────┬───────────────────────────────────────────┤
│ 历史会话侧边栏   │ 当前会话区域                                │
│                │                                           │
│ + 新建会话      │   欢迎语 / 推荐提示词                       │
│ 会话列表         │   推荐问题                                 │
│                │                                           │
│                │   消息流区域                                │
│                │                                           │
│                │   输入框区域                                │
└────────────────┴───────────────────────────────────────────┘
```

### 手机 H5 布局

* 左侧会话侧边栏改为 Drawer
* 顶部有“会话列表”按钮
* 主区域上下结构
* 输入框固定底部
* 推荐问题显示在空状态和新会话状态

## 9.2 左侧历史会话侧边栏

必须包含：

* 新建会话按钮
* 会话搜索框
* 会话列表
* 当前选中高亮
* 每个会话显示：

  * 标题
  * 最近更新时间
  * 可选菜单：重命名 / 删除

### 交互要求

* 点击“新建会话”后，右侧进入空白新会话状态
* 点击历史会话后加载该会话消息
* 移动端点击会话后自动关闭 Drawer

## 9.3 当前会话主区域

分为三种状态：

### 状态一：空状态 / 新建会话状态

页面内容居中显示：

* 产品欢迎语
* 一句简短引导文案
* 提示词标签区
* 推荐问题列表
* 中间输入框

示意：

```text
           AI企业助手
   你可以问我产品、文档、订单、流程相关问题

   [产品介绍] [销售话术] [报价政策] [售后说明]

   你可以这样问：
   - 这款产品适合哪些客户？
   - 新人销售如何快速上手？
   - 订单延迟如何回复客户？
   - 这个功能的使用方式是什么？

                [ 输入框 ]
```

### 状态二：对话进行中

页面显示：

* 消息列表
* 回答流式输出
* 来源引用
* 工具调用状态
* 底部输入框

### 状态三：加载状态

* 消息区域显示骨架屏或 loading
* 发送按钮禁用
* 输入框可根据策略禁用或允许中断

## 9.4 输入框区域

必须固定在当前会话区域底部。

### 包含元素

* 多行输入框
* 发送按钮
* 停止生成按钮
* 清空输入按钮
* 可选附件上传入口（预留）
* 可选模型切换入口（预留）

### 交互规则

* Enter 发送
* Shift + Enter 换行
* 发送中显示停止按钮
* 空输入不可发送
* 发送后自动清空输入框

## 9.5 提示词与推荐问题

输入框上方要展示两类内容：

### 提示词标签

短标签形式：

* 产品知识
* 销售话术
* 使用教程
* 常见问题
* 订单查询
* 物流轨迹

点击后自动填入输入框或直接发送

### 推荐问题

列表形式，2~6 条即可：

* 这款产品适合哪些客户？
* 新员工怎么快速了解产品？
* 客户问价格高怎么回答？
* 如何查询订单状态？
* 售后问题怎么处理？

### 显示规则

* 新会话时显示
* 当前会话消息较少时显示
* 消息多了后可折叠或隐藏

## 9.6 消息卡片设计

每条消息需区分角色：

* 用户消息：右侧
* AI 消息：左侧
* 工具消息：中间或特殊提示块

AI 消息需要支持：

* Markdown 渲染
* 代码块
* 引用来源折叠面板
* 工具调用过程展示
* 复制回答
* 重新生成

## 20.2 `useAppStore`

管理：

* 侧边栏展开收起
* 当前设备类型
* 全局 loading
* 布局状态

## 20.3 `useChatStore`

管理：

# 23. 前端实现约束（给 AI 编码时必须遵守）

2. 必须支持从 1920px 到手机 H5 的响应式适配
3. 聊天页必须有左侧历史会话栏和新建会话按钮
4. 当前会话页必须有中间布局的空状态页面

6. 管理员角色必须具备：

   * 租户管理
   * 文档上传与管理
   * 日志管理
   * 工具管理
   * MCP 管理
   * 系统监控
7. 仪表盘必须展示：

   * 当前在线人数
   * 流量
   * Tokens
   * 调用趋势
8. 所有页面必须按角色动态控制菜单和路由权限
9. 所有表格页面在移动端必须可用，必要时改为卡片列表
10. 所有 API 请求必须封装到 `api/` 目录
11. 所有页面必须拆分为可维护组件
12. 项目必须提供基础 mock 数据或演示数据，便于本地运行
